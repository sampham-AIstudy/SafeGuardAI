NHIỆM VỤ: PHASE 3A — SafeRedirectResolver chống SSRF (module MỚI, CHƯA nối vào analyzer/orchestrator). Đây là phần BẢO MẬT quan trọng nhất: sai một chỗ là máy người dùng thành proxy tấn công mạng nội bộ. Đọc docs/UPGRADE_PLAN.md §3.6 (dòng ~268-288) và Phase 3 (dòng ~486-510). Tạo MỚI: codebase/url_analysis/resolver.py, tests/test_url_resolver.py. KHÔNG sửa file khác. Tuyệt đối KHÔNG gọi mạng thật trong test (fixture no_network chặn mọi socket trừ loopback; test với server thật CHỈ dùng 127.0.0.1 qua tham số kiểm thử bên dưới).

API:
```python
@dataclass
class Hop: url:str; status:int|None; location:str|None; ip:str|None
@dataclass
class RedirectChain: hops:list[Hop]; final_url:str|None; blocked_reason:str|None; error:str|None; elapsed_ms:float; from_cache:bool; antibot:dict|None  # antibot để Phase 3B điền
def is_public_destination(host:str, port:int, getaddrinfo=socket.getaddrinfo, timeout:float=2.0) -> tuple[bool,str,list[str]]   # (ok, reason, ips)
class SafeRedirectResolver:
    def __init__(self, mode="shorteners", max_hops=5, per_hop_timeout=3.0, total_budget=6.0, max_body_bytes=65536,
                 transport=None, getaddrinfo=socket.getaddrinfo, cache_ttl_s=3600, cache_max=512, ip_validator=None, lists=None)
    def should_resolve(self, parsed_url) -> bool     # mode off: never; shorteners: chỉ khi host thuộc shorteners/redirectors trong url_lists.json; all: mọi URL http(s)
    def resolve(self, url:str) -> RedirectChain
```
Quy tắc BẮT BUỘC (mỗi quy tắc một nhóm test):
1) Chỉ scheme http/https; port chỉ 80/443 (mọi port khác bị chặn, ghi blocked_reason); từ chối userinfo trong URL cần resolve; từ chối file:, ftp:, gopher:, data:, javascript:, ws:.
2) Chuẩn hóa host bằng url_analysis.parse.parse_url (effective_host, đã xử lý IP thập phân/hex/octal/rút gọn, backslash, %xx) TRƯỚC khi kiểm tra; không dùng urlsplit().hostname.
3) Từ chối tên: localhost, *.localhost, *.local, *.internal, *.localdomain, *.lan, *.home.arpa, metadata.google.internal, host không có dấu chấm (tên NetBIOS), 'metadata', IP literal bị cấm.
4) is_public_destination: resolve TẤT CẢ A/AAAA bằng getaddrinfo trong một thread có timeout (getaddrinfo không có tham số timeout; dùng concurrent.futures với future.result(timeout) và KHÔNG chờ thread khi timeout - dùng executor.shutdown(wait=False, cancel_futures=True)); từ chối nếu bất kỳ IP nào `not ipaddress.ip_address(ip).is_global` (bao gồm private 10/8, 172.16/12, 192.168/16, loopback, link-local 169.254/16 gồm 169.254.169.254, CGNAT 100.64/10, multicast, reserved, unspecified 0.0.0.0, IPv6 ::1, fc00::/7, fe80::/10, ::ffff:127.0.0.1 (IPv4-mapped: kiểm tra địa chỉ IPv4 bên trong), 64:ff9b::/96 (NAT64 chứa IP private), 2002::/16 6to4 chứa IP private); kết quả rỗng/lỗi => chặn (fail closed).
5) GHIM IP chống DNS rebinding: sau khi kiểm tra, kết nối TCP tới ĐÚNG IP đã kiểm tra (không resolve lần hai), TLS với server_hostname=host (SNI + verify bật bằng ssl.create_default_context()), header Host đúng. Transport mặc định dùng http.client.HTTPConnection/HTTPSConnection subclass (ghi đè connect()) KHÔNG dùng urllib/requests (chúng đi qua biến môi trường HTTP_PROXY). transport tiêm được cho test: transport(method, scheme, ip, port, host, path_and_query, headers, timeout) -> (status:int, headers:dict[str,str] (khóa chữ thường), body:bytes).
6) Yêu cầu: HEAD trước; nếu 405/501/403 trên HEAD thì GET và CHỈ đọc tối đa max_body_bytes (64KB) rồi đóng; header Accept-Encoding: identity (không giải nén => chống zip bomb), không Cookie, không Referer, User-Agent trung thực 'SafeGuardAI-LinkChecker/1.0'; không gửi Authorization; không đọc body của HEAD. Không chạy JavaScript; chỉ phân tích `<meta http-equiv="refresh" content="N;url=...">` (regex tuyến tính giới hạn) trong 64KB đầu.
7) Redirect: theo Location (301/302/303/307/308) và meta refresh; mỗi hop PHẢI qua lại toàn bộ kiểm tra 1-4 (kể cả hop sau chuyển sang IP private => chặn, blocked_reason có 'private'); Location tương đối được ghép đúng (urljoin); tối đa max_hops; phát hiện vòng lặp (URL đã thấy); tổng thời gian không vượt total_budget (time.monotonic, kể cả thời gian DNS); mỗi lệnh gọi transport nhận timeout = min(per_hop_timeout, còn lại của budget); khi hết budget trả kết quả một phần với error='budget_exceeded'.
8) Cache: dict có khóa (url chuẩn hóa) giới hạn cache_max (LRU), TTL cache_ttl_s, thread-safe (Lock); kết quả bị chặn cũng cache ngắn (60s) nhưng đánh dấu from_cache.
9) Biến môi trường: nếu get_settings().network_enabled là False hoặc offline thì resolve() KHÔNG gọi transport/getaddrinfo, trả blocked_reason='network_disabled'. mode đọc từ get_settings().redirect_mode nếu không truyền.
10) Không bao giờ raise ra ngoài resolve(): mọi lỗi (timeout, SSL, kết nối bị từ chối, header bẩn, Location rất dài >2048, quá nhiều header) -> RedirectChain.error.
11) ip_validator (tham số kiểm thử, mặc định None = dùng is_public_destination chuẩn): CHỈ dùng trong test để cho phép 127.0.0.1 khi dựng server thật; mặc định production phải luôn chặn loopback.
Tests (tests/test_url_resolver.py), tất cả mock getaddrinfo/transport (không mạng thật): SSRF — mỗi mục là một test tham số hóa: IP literal 127.0.0.1, 10.0.0.1, 172.16.0.1, 192.168.1.1, 169.254.169.254, 100.64.0.1, 0.0.0.0, [::1], [::ffff:127.0.0.1], [64:ff9b::7f00:1], [2002:7f00:1::], decimal 2130706433, hex 0x7f000001, octal 0177.0.0.1, rút gọn 127.1, 'localhost', 'x.localhost', 'foo.internal', 'metadata.google.internal', host một nhãn; getaddrinfo giả trả IP private cho tên công khai ('evil.example' -> 10.0.0.5), trả hỗn hợp [8.8.8.8, 127.0.0.1] => chặn, trả [] => chặn, ném lỗi => chặn, treo 30s => chặn trong <= timeout+0.5s; DNS rebinding giả lập (lần 1 trả IP công khai, lần 2 trả 127.0.0.1) => kết nối đến IP đã kiểm tra lần 1, transport nhận đúng ip đó và getaddrinfo chỉ được gọi 1 lần cho mỗi hop; redirect hop 2 tới IP private/localhost/metadata => chặn và chain.hops giữ hop 1; port 8080/22/25/6379 và scheme file:/ftp:/gopher:/javascript:/data: => chặn; userinfo => chặn; >5 hop => error 'too_many_hops'; vòng lặp A->B->A; budget: transport giả sleep 0.2s mỗi hop, total_budget=0.5 => kết thúc <= 0.5+0.5s với budget_exceeded; body > 64KB bị cắt đúng 65536 byte (transport giả trả 1MB, kiểm bytes đọc); HEAD 405 -> GET; meta refresh (có và không dấu nháy, content='0; URL=...', 'url' viết hoa); Location tương đối; Location quá dài; Accept-Encoding/UA/không Cookie/Referer trong request giả; cache hit/miss/TTL/LRU/thread-safety (16 luồng); network_disabled => transport 0 lần gọi; mode off/shorteners/all với host shortener và host thường; transport raise => error không raise ra ngoài; ReDoS meta refresh (body 64KB '<meta '*10000) < 0.2s. Thêm 2 test với server HTTP THẬT trên 127.0.0.1 (thread, ip_validator cho phép loopback): redirect 302 chuỗi 2 hop trả final_url đúng, và máy chủ kiểm tra thấy header Host đúng + không có Cookie/Referer + không bị gọi lần hai; server treo => chain kết thúc theo timeout.
Mutation (tự thử >= 8, hoàn tác sau mỗi lần): bỏ kiểm is_global; bỏ kiểm ipv4-mapped; bỏ kiểm hop sau; resolve lần hai; bỏ giới hạn port; bỏ giới hạn 64KB; bỏ timeout DNS; bỏ phát hiện vòng lặp; cho userinfo. Mutation nào sống sót thì thêm test.
