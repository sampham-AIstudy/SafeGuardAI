# AI agent architecture study

Research recommendation, 2026-11-19. See the [end-to-end target architecture](safeguard-target-architecture.html), the [proposed Detection diagram](agent-detection.html), and the [evaluation protocol](agent-evaluation.md).

## Recommendation

Keep one Agent Controller in Detection. Give it versioned analysis state and the ability to choose a bounded check whose result could change the assessment. Keep source access and execution limits under Execution Host control. Compare that design with the existing controller before adding model routing. A single controller can use multiple models through Model Access.

The evidence supports selecting a research direction. SafeGuard has functional evidence for tool use and warning delivery. It has no comparative result that establishes a best agent architecture or model. The recommendation prioritizes the smallest change that can add information while retaining the existing Detection interfaces.

## Architecture choices

| Direction | Mechanism and useful conditions | Cost or failure mode | Research disposition |
|---|---|---|---|
| Reactive single agent | Use the current loop. The model chooses actions from a bounded catalog and can conclude immediately. ReAct tests the underlying feedback pattern. [ReAct](https://ysymyth.github.io/papers/react_llm.pdf) | Every extra round consumes time and context. Tool use adds value only when the observations help the decision. | Keep as the control and fallback architecture. |
| Stateful agent with selective acquisition | Carry source-linked facts and unresolved questions across observations. Acquire more information when a permitted check could change the assessment. [Active Feature Acquisition](https://proceedings.neurips.cc/paper/2018/hash/e5841df2166dd424a57127423d276bbe-Abstract.html) | Persistent synthesis can carry stale or incorrect inferences into later turns. Version the state, keep references to originals, and revalidate facts at the current boundary. | First research candidate. It changes evidence handling while retaining one controller and the existing Host. |
| Plan and execute inside the agent | Select a batch of independent checks before execution. ReWOO studies a related way of separating planning from external observations. [ReWOO](https://arxiv.org/abs/2305.18323) | A batch can save calls. A premature plan can spend resources on an irrelevant check or miss an opportunity revealed by another result. | Consider batching when checks have independent inputs and one result cannot change the need for another. |
| Multiple models under one controller | Route to compatible models or request a bounded second assessment. [RouteLLM](https://arxiv.org/abs/2406.18665) · [FrugalGPT](https://arxiv.org/abs/2305.05176) | Routing errors can suppress useful analysis. A second model can share the first model's blind spots. Extra calls add latency and may widen the data boundary. | Second candidate. Evaluate only after fixed-model runs reveal complementary strengths. Start with capability and availability restrictions. Calibrate any learned uncertainty rule separately. |
| Multiple agents or search over several reasoning paths | Obtain independent candidates or explore multiple action paths before selecting an answer. [Multi-Agent Debate](https://proceedings.mlr.press/v235/smit24a.html) · [Language Agent Tree Search](https://proceedings.mlr.press/v235/zhou24r.html) | More calls and more opportunities for correlated error. Published debate results vary across methods and settings. | Revisit only when disagreements or missed paths remain a measured bottleneck and a simple second assessment is a credible baseline. |
| Hierarchical or recursive retrieval | Query small subsets of a large external context and revisit the original as needed. [Recursive Language Models](https://arxiv.org/abs/2512.24601) · [MuRAG](https://aclanthology.org/2022.emnlp-main.375/) | Retrieval can miss decisive evidence. Recursive calls increase worst-case latency. | Revisit when long or multimodal histories show measured evidence loss and simpler scoped retrieval falls short. Start with bounded read-only retrieval. |

These studies establish methods worth comparing. Their domains, models, and budgets differ from SafeGuard. In particular, results on multimodal question answering establish a retrieval capability for the studied tasks. They leave streaming scam detection and Vietnamese evidence quality open. PreScam studies progression prediction in the same broad domain and uses a different target from SafeGuard's warning decision. [PreScam](https://arxiv.org/abs/2605.12243)

## Proposed Detection contracts

| Exchange | Minimum contents and ownership |
|---|---|
| **Observed boundary** | Host supplies the existing conversation boundary, permitted parts, and execution budget. Agent actions resolve only against that boundary and access context. |
| **Tool observation** | Host supplies the source reference, tool and version, result, processing status, and input identity. Preserve the difference between an observation, a sender claim, a tool inference, and a separately verified fact. Readers report missing, unsupported, and failed processing distinctly. |
| **Conversation analysis state** | Agent proposes a bounded set of source-linked facts, unresolved questions, and previous assessment references. Host checks scope and expected version before committing. Store source material in the existing Memory blocks. A failed state write leaves the earlier committed state available. |
| **Assessment** | Keep the existing verdict and evidence groups for downstream consumers. An assessment cites the observations that support its reasoning and identifies material gaps. A material gap can yield `insufficient_evidence`. A failed invocation follows the existing non-assessment path. Warning Policy receives only the validated, committed assessment or the existing failure outcome. |

Resolve repeated artifacts by original identity when known. Preserve every observed source reference and count repeated presentations of the same artifact as shared evidence. Keep contradictory observations with their separate sources and mark the claim unresolved until stronger evidence resolves the conflict. Treat new messages as new observation boundaries. Recheck scope before reusing state and reject a stale commit. When a check fails, record which observations were unavailable and assess whether the remaining evidence can support a verdict. [W3C PROV](https://www.w3.org/TR/prov-dm/) · [FEVER](https://aclanthology.org/N18-1074/) · [ALCE](https://aclanthology.org/2023.emlp-main.398/)

Select at most one next check at a time unless checks are independent. Prefer a check that answers a material unresolved question. Stop when the current evidence supports the assessment, meaningful checks are exhausted, or the Host denies further work under its limits. Partition state by conversation and cache successful tool observations by source identity and processor version inside the applicable access scope. A prior model verdict retains its provenance as a verdict.

## Decision rules

Keep the current agent as the reference if selective acquisition does not improve grounded decisions on the paired evaluation. Advance the stateful design if it retrieves consequential evidence and improves warning behavior within the agreed cost and latency constraints. Advance multi-model routing only if fixed-model results establish complementary strengths and routing improves the measured quality and cost trade-off against a fixed model. An inconclusive result keeps the simpler candidate and leaves the research question open. [Evaluation protocol](agent-evaluation.md)
